# 00 — Start Here: PsyLattice in One Document

## What PsyLattice is

PsyLattice is being built as an integrated psychology platform spanning **Research**, **Self**, and **Clinical** workflows. The strongest current product direction is to remove the technical barrier between a psychologist’s research idea and a clean, reproducible dataset.

The Research product should not be understood as “a website with questionnaires” or “an online cognitive-task library.” Its intended workflow is:

**Build → Save → Reuse → Assemble → Collect → Connect → Analyse → Interpret → Export**

A psychologist should be able to create or reuse research components, assemble a complete protocol, run participants, combine different data modalities, inspect quality, conduct practical analysis, use AI as a context-aware interpretation layer, and export clean plus lossless raw data without coding/data-engineering expertise.

## Core product promise

A useful positioning statement used during product planning was:

**Psychological research without the technical barrier.**

Another:

**The research workspace built for psychologists.**

The moat is not “we have lots of tasks.” The moat is the connected workflow and the product’s understanding of psychological data.

## The most important architectural principles

### 1. Reusable components, complete studies

Cognitive Lab owns reusable cognitive task definitions and batteries.

Questionnaire Library owns reusable questionnaire definitions/versions.

Study Builder owns the actual participant protocol and cross-type ordering.

### 2. Exact versions are pinned

Studies and batteries pin exact published cognitive task versions. Published definitions should not mutate beneath an existing study.

### 3. Batteries orchestrate; they do not duplicate results

A battery is a reusable ordered package of cognitive task versions. Each task still runs its own normal runtime and stores ordinary `cognitive_task_sessions` and `cognitive_trial_results`.

### 4. Research data remains lossless

PsyLattice should provide convenient clean sheets **and** preserve complete raw records. Never trade one for the other.

### 5. AI interprets authoritative data

AI should not be the scoring engine. Deterministic scoring remains code/data. AI uses the stored results as context.

### 6. UX should be approachable without dumbing down capability

Do not add separate Beginner/Advanced modes. Make one interface understandable enough for thesis students and strong enough for serious researchers.

## Current Cognitive Lab state

Generic/standardized-style runner tasks exist for multiple classic paradigms, including a core set around RT, inhibition, attention, working memory, visual search, task switching, lexical decision, etc.

Dedicated engines now exist for:

- Stop-Signal
- Corsi Block Tapping
- PsyLattice Card Sorting (WCST-style but explicitly not the proprietary/official WCST)
- BART
- image-based Mental Rotation

Dedicated Research/Data integration exists for these later tasks, with stable participant-level variables, raw records, Excel sheets, Study Associations compatibility, quality review, and AI context.

Cognitive Batteries are implemented through three phases:

- reusable/versioned Battery Builder;
- battery execution + Study Builder integration;
- battery reporting/export/research integration.

## Current Thesis Builder state

The Research sidebar item is **Thesis Builder**.

It has evolved into a Word-like, paged research writing workspace with:

- nested folders within folders;
- visual file/document navigator;
- collapsible file navigator;
- focus mode and true full-screen mode;
- sticky file panes and sticky editor controls;
- page stack rather than one infinitely tall document;
- zoom controls;
- default **Free form** mode;
- academic presets (APA 7 Student, APA 7 Professional, MLA 9, Chicago/Turabian, IEEE, Custom/institution-specific);
- interactive per-side margins;
- manual Save only — autosave was intentionally removed;
- unsaved-change warnings;
- import existing DOCX/HTML/Markdown/TXT work into a selected folder;
- PDF and Word export, A4/Letter selection;
- table creation/editing/resizing;
- image upload, resizing, drag positioning, wrap modes, and deletion;
- revisions/recovery snapshots;
- Writing AI with explicit document-read permission;
- selection-safe text color, highlight, and font-size controls.

Do not reintroduce the previously fixed selection/focus bugs or autosave.

## Current collaboration/deferred decisions

- Research collaborator / Team & Permissions is deliberately deferred because the web collaboration workflow was not functional enough. Do not add the old planned Phase 2J team-permissions migration unless the collaboration feature is explicitly restarted.
- Native push notifications are deferred. Follow-up delivery remains email-based for now; a unified notification system across Self/Clinical/Research/mobile is planned later.
- iOS/Apple Watch support is planned; Android/Health Connect work is ahead of it.

## Export is a product priority

Before expanding into a huge advanced-statistics package, keep the export system strong:

- complete raw records;
- researcher-friendly Excel;
- participant-level summaries;
- questionnaires;
- cognitive tasks/trials;
- demographics;
- consent metadata where appropriate;
- EMA/ESM/ambulatory records;
- follow-ups;
- timing/data-quality diagnostics;
- future data sources.

Common clean/statistics surfaces include `Analysis_Wide`, `Analysis_Compatible`, `Variable_Map`, codebooks, import guidance, and SPSS/jamovi/JASP-friendly output.

## What a new engineer should never do on day one

- Do not replace `app/researcher/page.tsx` from an old ZIP.
- Do not disable RLS to “fix permissions.”
- Do not expose service-role credentials to client code.
- Do not delete research rows to make a dashboard look clean.
- Do not add automatic participant exclusion from quality flags.
- Do not change task scoring definitions casually.
- Do not call PsyLattice Card Sorting the official WCST.
- Do not show research-only scores to participants by default.
- Do not give Thesis Builder AI silent access to the paper.
- Do not re-enable autosave in Thesis Builder.
- Do not assume a VS Code Problems count means hundreds of independent bugs.
